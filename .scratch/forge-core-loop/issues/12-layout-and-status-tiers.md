# 12 — 布局打磨与状态可见性分层

**What to build:** 界面的最终形态。三个结构性方案已经在原型里比过（`prototypes/ui-layout.html`），
这一票把选定的那个做完整。

定下来的是**双栏分屏**（左对话、右预览），但吸收抽屉方案的优点：
**生成早期预览收起**——那时对话是唯一有信息量的东西，预览是个空白画布；
**首个文件写入后展开**。这个时序和骨架先行正好对齐。

同时上线三层状态可见性。这三层各有分工，**不要合并**。

**Blocked by:** 04 — Emma 先规划，文件树骨架填入；05 — 构建失败有界自修复；06 — 中途停止不丢文件；11 — 门控失败就停下，不自动重试

（阻塞较多是因为"三层状态可见性"要等 05/06/11 的状态都存在了才有意义。
若想更早做完布局骨架，可以只做收起时序和移动端，把三层状态拆成单独一票。）

**Status:** ready-for-agent

### 布局

- [ ] 双栏：左侧对话、右侧预览，并列可见
- [ ] 生成早期（understanding / planning 阶段）预览收起，对话占满宽度
- [ ] 首个文件写入后预览展开（与骨架先行的时序对齐）
- [ ] 预览可手动收起/展开（顶部按钮）
- [ ] 移动端（窄屏）退化为对话单栏，预览通过全屏覆盖访问
- [ ] 预览区提供新标签页打开的出口
- [ ] 空状态：三个可点击的具体样例 + "不需要写代码，也不需要注册"
- [ ] 对话栏宽度不小于约 340px——文件树要能不折行显示 4 行，门控错误卡片要能排下代码块和两个按钮
- [ ] 主题跟随系统，以亮色为主（暗色不做精细打磨）

### 三层状态可见性

- [ ] **顶栏**显示全局状态（生成中 / 运行中 / 需要确认），在状态机迁移时更新
- [ ] **消息头部**显示当前动作（"正在写 src/App.tsx"），在每个工具调用时更新
- [ ] **活动日志**折叠区显示完整事件流，默认折叠、可展开
- [ ] 三层**同时存在且不合并**——顶栏是全局、消息头是当前动作、日志是完整流水
- [ ] 活动日志用 transient 进度事件填充（`plan_ready` / `gate_started` / `sandbox_state`），不占持久化存储

### 沙箱状态

- [ ] 沙箱正在恢复时（约 1 秒）显示"正在恢复"提示，不无声
- [ ] 沙箱已被回收时显示明确提示，而不是一个坏掉的 iframe
