# 11 — 门控失败就停下，不自动重试

**What to build:** 安全检查没通过时，生成**停下等用户确认**，而不是自己重试。

这是和构建失败**性质完全不同**的失败，必须区别对待：

- 构建失败是技术问题 → 自修复合理
- 门控失败意味着**生成的数据隔离策略不安全** → 自动重试有掩盖问题的风险

用户不该在不知情的情况下拿到一个"看起来成功了"但实际不安全的生成应用。
所以这条边上不接自修复循环，接了反而是 bug。

呈现上有一件事必须说清楚：**"已回滚，未对外暴露任何数据"**——
用户需要知道这次失败是安全的，否则会以为数据泄漏了。

**Blocked by:** 03 — 生成可跑应用并预览

**Status:** done

- [ ] 状态机里有 `gating → gate_failed` 这条边，且**它不通向 `autofixing`**
- [ ] 门控失败时发出明确的事件，前端展示专属的错误卡片（不是通用错误样式）
- [ ] 卡片文案明确说明"这是停下等你确认，不是自动重试"
- [ ] 卡片文案明确说明"已回滚，未对外暴露任何数据"
- [ ] 卡片显示检测到的具体策略标识（例如策略名和表名），即使非技术用户看不懂代码，也能看出它指的是哪里
- [ ] 提供"让 Alex 重写"和"查看详情"两个操作
- [ ] 选择"让 Alex 重写"后，把门控的失败原因注入下一轮 prompt
- [ ] 测试（**用假门控**）：让假沙箱的迁移步骤返回一次门控拒绝，断言：
  - 事件流里出现 `gate_failed` 语义
  - **不出现任何重试事件**（这是本票最关键的断言）
  - 已写入的文件保留

**注**：真实的门控实现（RLS 模板注入 + Security Advisor 扫描）属于 `forge-app-backend`。
本票只做状态机里的这条边和它的呈现，门控本身由端口注入、测试时用假的。
