# 05 — 构建失败有界自修复

**What to build:** 构建报错时 Alex 自己修，而不是把错误甩给用户。
但"自己修"是**有界的**——最多 3 次，超了就停下来说清楚，不无限转圈。

用户看到"出了点问题，Alex 正在自己修"和一句人话说明错误，原始错误折叠在后面。
修完了预览更新，修不好就明确告知并停止。
**已写入的文件在整个过程中始终保留**——重试不从零开始。

**Blocked by:** 03 — 生成可跑应用并预览

**Status:** done

- [ ] 构建命令失败时，orchestrator 进入 `autofixing` 状态而不是终止
- [ ] 错误上下文（报错信息）注入下一轮的 prompt，Alex 看到"上次构建的错误是这个"
- [ ] 重试最多 3 次（`building → failed → autofixing` 循环最多 3 圈）
- [ ] 第 3 次仍失败时进入 `gave_up`，发出明确的错误事件，不再重试
- [ ] 对话面板里自修复期间显示"出了点问题，Alex 正在自己修（第 N 次）"
- [ ] 错误以一句人话呈现，原始错误文本折叠在"查看详情"后面
- [ ] 超限后显示"失败原因 + 下一步建议"（例如"建议换一个更简单的描述重试"）
- [ ] 自修复期间已写入的文件**全部保留**，不会因为重试被清空
