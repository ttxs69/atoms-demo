## Comments

### 2026-09-12 实测发现：第二轮在无历史时会产生破坏性重写

E2B key 配置后的首次真实端到端验证（deepseek-chat）暴露的约束：

- 第一轮：「做一个 hello page」→ `index.html`（1083B，含 Hello Forge）
- 第二轮（同一 sessionId）：「在 `</body>` 前加一行注释」→ 模型把整个文件
  **重写**成 381B 的 Vite 模板（`/src/main.tsx` + `<div id="root">`），
  第一轮内容**静默丢失**。注释确实加上了。

根因：orchestrator 每轮只把**当前** user message 传给模型，没有已写文件的任何信息
（多轮历史本来就是本票范围）。模型于是按默认假设重建。

**对本票的影响**：这不是"跳过 install"那样的优化项，而是**正确性前提**——
在注入共享历史（至少：已写文件清单 + 第一轮以来的对话）之前，
第二轮对话对用户的工作区是**破坏性的**。本票的验收标准应包含：
第二轮修改后，未被要求改动的文件内容保持逐字节不变。
